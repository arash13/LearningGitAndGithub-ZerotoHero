# هفته 11 | Fork، مشارکت متن‌باز و Rulesets

**فاز:** 3 | **وضعیت:** طرح درس، آماده تکمیل تعاملی هنگام رسیدن به این هفته

## نتیجه مورد انتظار

به پروژه متعلق به دیگری مشارکت قابل بررسی ارائه کنی.

## مدل ذهنی

Fork در GitHub کپی مالکیتی مخزن است؛ Branch درون یک مخزن به تاریخچه موجود اشاره می‌کند. برای مشارکت باید همگام‌سازی با upstream را بفهمی.

## واژه‌ها و دستورهای کلیدی

- `git remote add upstream URL`
- `git fetch upstream`
- `git switch -c fix/readme`
- `git push -u origin fix/readme`

> هر دستور را قبل از اجرا از نظر پوشه فعلی، شاخه، تغییرات ثبت‌نشده و اثر بر Remote بررسی می‌کنیم. این فهرست، جایگزین آموزش عملی جلسه نیست.

## مثال و آزمایش هفته

**سناریو:** یک مخزن تمرینی مجاز را Fork کن، اشتباه مستنداتی را اصلاح کن و PR با شرح تست بده.

گزارش باید شامل وضعیت اولیه، کار انجام‌شده، نتیجه قابل مشاهده، یک اشتباه و نحوه بررسی یا اصلاح آن باشد. نتیجه را با Link به Commit/PR/Issue یا خروجی سانسورشده ثابت کن.

## آزمون پایان هفته

1. Fork چه فرقی با Clone دارد؟
2. upstream چیست؟
3. Branch Protection با Rulesets چه نسبتی دارد؟

4. **آزمون عملی:** سناریو را با روش خودت کامل اجرا کن، وضعیت نهایی را ثابت کن و توضیح بده چرا این راهکار را انتخاب کردی.

## نکته ایمنی

برای مشارکت در مخزن واقعی، راهنمای CONTRIBUTING و قوانین آن را رعایت کن.
