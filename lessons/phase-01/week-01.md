# هفته ۰۱ | از صفر: Windows، ترمینال، Git و GitHub

**فاز:** ۱ | **زمان پیشنهادی:** ۴ تا ۷ ساعت | **وضعیت:** آماده تدریس و تمرین

> پیش‌فرض این درس: حتی یک دستور Git بلد نیستی. با همین پیش‌فرض جلو می‌ریم.

## هدف‌های قابل سنجش

در پایان باید بتوانی (۱) تفاوت Git و GitHub را با مثال توضیح بدهی، (۲) پوشه فعلی را در Git Bash پیدا کنی، (۳) نصب و هویت Git را بررسی کنی، (۴) این مخزن را روی Windows دریافت کنی، (۵) تشخیص بدهی چه زمانی داخل یک مخزن Git هستی.

## بخش ۱ | چرا اصلاً Git؟

فرض کن یک فایل گزارش داری و هر روز ویرایشش می‌کنی. اگر فقط `report-final-v2-really-final.txt` بسازی، تشخیص تغییرها و برگشت به نسخه درست سخت می‌شود. Git تاریخچه تغییرات پروژه را مدل می‌کند.

- **Git** ابزار کنترل نسخه است و بیشتر عملیات روزانه‌اش محلی انجام می‌شود.
- **GitHub** سرویس میزبانی مخزن و همکاری است؛ بعداً Issue، Pull Request، Actions و امکانات سازمانی آن را یاد می‌گیریم.
- **Repository** پوشه پروژه به همراه اطلاعات تاریخچه Git است.
- **Commit** یک ثبت در تاریخچه است؛ صرفاً ذخیره کردن فایل با Ctrl+S معادل Commit نیست.

### سؤال توقف: اگر اینترنت قطع شود، آیا می‌توان در مخزن موجود Commit جدید ساخت؟ چرا؟

## بخش ۲ | آشنایی با Git Bash

برنامه Git Bash را از Start باز کن. بعد دستورهای زیر را **به‌ترتیب** اجرا کن:

```bash
pwd
ls
cd ~
pwd
mkdir -p git-learning
cd git-learning
pwd
```

- `pwd`: مسیر فعلی را چاپ می‌کند.
- `ls`: نام فایل‌ها و پوشه‌های داخل مکان فعلی را نشان می‌دهد.
- `cd ~`: به پوشه خانه کاربر می‌رود.
- `mkdir -p git-learning`: پوشه تمرینی می‌سازد؛ اگر موجود باشد معمولاً خطایی نمی‌دهد.
- `cd git-learning`: وارد پوشه می‌شود.

**نکته Windows:** در Git Bash ممکن است مسیر در قالب `/c/Users/...` نمایش داده شود. برای پوشه‌هایی که نامشان فاصله دارد، مسیر را داخل کوتیشن قرار بده.

### خطای آزمایشی امن

```bash
cd this-folder-does-not-exist
pwd
```

خطای `No such file or directory` طبیعی است. `pwd` را بررسی کن؛ دستور `cd` ناموفق، پوشه فعلی را عوض نمی‌کند. حالا خودت علت را توضیح بده.

## بخش ۳ | نصب و هویت Git

اگر هنوز نصب نکرده‌ای، از [راهنمای Windows](../../docs/WINDOWS-SETUP.md) شروع کن.

```bash
git --version
git config --global user.name
git config --global user.email
```

این سه دستور **اطلاعات را می‌خوانند** و چیزی منتشر نمی‌کنند. اگر نام یا ایمیل خالی بود، طبق راهنمای نصب مقدار مناسب خودت را تنظیم کن.

```bash
git config --global user.name "Your Display Name"
git config --global user.email "YOUR_GITHUB_NOREPLY_EMAIL"
```

مقادیر نمونه را با مقدار آگاهانه خودت جایگزین کن. برای مخزن عمومی، ایمیل `noreply` حساب GitHub گزینه مناسب‌تری برای حریم خصوصی است.

## بخش ۴ | گرفتن پروژه از GitHub

وقتی داخل پوشه `git-learning` هستی:

```bash
git clone https://github.com/arash13/LearningGitAndGithub-ZerotoHero.git
cd LearningGitAndGithub-ZerotoHero
git status
git remote -v
git log --oneline -3
```

### خروجی‌ها را چطور تفسیر کنیم؟

- `git clone` مخزن را در پوشه‌ای تازه دانلود می‌کند و Remote پیش‌فرضی معمولاً به نام `origin` تنظیم می‌کند.
- `git status` به تو می‌گوید روی چه شاخه‌ای هستی و آیا تغییری در فایل‌های کاری داری.
- `git remote -v` آدرس Remoteهای تعریف‌شده را نشان می‌دهد.
- `git log --oneline -3` سه Commit آخر را اگر وجود داشته باشند در یک خط برای هر Commit نمایش می‌دهد.

تاریخچه به مرور با Commitهای واقعی دوره ساخته می‌شود. **فعلاً `push` یا `reset` اجرا نکن.** دستور `git init` هم در پوشه‌ای که Clone شده لازم نیست.

## بخش ۵ | مینی‌چالش

بدون کپی کردن دستورها از این صفحه:

۱. از یک پنجره جدید Git Bash به پوشه مخزن برو.
۲. نسخه Git، مسیر فعلی، شاخه فعلی و Remote را بررسی کن.
۳. در سه جمله توضیح بده آیا `git status` چیزی را روی GitHub تغییر می‌دهد یا نه.
۴. یک خطای مسیر اشتباه را عمداً بازسازی و بعد اصلاح کن.

## آزمون هفته ۱ (پاسخ‌نامه عمداً داخل فایل نیست)

**مفهومی**
1. تفاوت Git و GitHub را با مثال دفترچه یادداشت شرح بده.
2. `clone` چه چیزی می‌سازد؟ `init` چه زمانی مناسب‌تر است؟
3. تفاوت Save در ویرایشگر و Commit در Git چیست؟

**پیش‌بینی و عیب‌یابی**
4. وقتی خارج از مخزن `git status` بزنی، انتظار چه نوع پیامی داری؟ دلیلش چیست؟
5. اگر `cd unknown-folder` خطا دهد، دستور بعدی `pwd` چه چیزی را نشان می‌دهد؟

**عملی**
6. خروجی غیرحساس `git --version`، `pwd`، `git status`، `git remote -v` را در گزارشی کوتاه توضیح بده. اطلاعات شخصی مسیر را در صورت نیاز حذف کن.
