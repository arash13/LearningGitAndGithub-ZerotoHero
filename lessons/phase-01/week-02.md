# هفته 02 | Init، Add، Commit و Staging

**فاز:** 1 | **وضعیت:** طرح درس، آماده تکمیل تعاملی هنگام رسیدن به این هفته

## نتیجه مورد انتظار

سه ناحیه Working Tree، Staging Area و Repository را از هم تشخیص بده و Commit انتخابی بساز.

## مدل ذهنی

ذخیره‌کردن فایل فقط Working Tree را تغییر می‌دهد. دستور add تغییر موردنظر را برای ثبت انتخاب می‌کند و commit از محتوای انتخاب‌شده یک نقطه تاریخچه می‌سازد.

## واژه‌ها و دستورهای کلیدی

- `git init`
- `git status`
- `git add notes.txt`
- `git diff --staged`
- `git commit -m "docs: add first notes"`

> هر دستور را قبل از اجرا از نظر پوشه فعلی، شاخه، تغییرات ثبت‌نشده و اثر بر Remote بررسی می‌کنیم. این فهرست، جایگزین آموزش عملی جلسه نیست.

## مثال و آزمایش هفته

**سناریو:** در یک پوشه آزمایشی تازه Git init کن، دو فایل بساز، فقط یکی را stage و commit کن؛ ثابت کن فایل دیگر هنوز ثبت نشده.

گزارش باید شامل وضعیت اولیه، کار انجام‌شده، نتیجه قابل مشاهده، یک اشتباه و نحوه بررسی یا اصلاح آن باشد. نتیجه را با Link به Commit/PR/Issue یا خروجی سانسورشده ثابت کن.

## آزمون پایان هفته

1. چرا add با commit یکسان نیست؟
2. اگر پس از add فایل را دوباره ویرایش کنی، Commit کدام نسخه را ذخیره می‌کند؟
3. چطور پیش از Commit تغییر انتخاب‌شده را بررسی می‌کنی؟

4. **آزمون عملی:** سناریو را با روش خودت کامل اجرا کن، وضعیت نهایی را ثابت کن و توضیح بده چرا این راهکار را انتخاب کردی.

## نکته ایمنی

در پوشه Clone شده دوباره init لازم نیست. تمرین init را در پوشه‌ای جدید انجام بده.
