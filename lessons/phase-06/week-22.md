# هفته 22 | GitHub CLI، REST و GraphQL API

**فاز:** 6 | **وضعیت:** طرح درس برای تکمیل و تمرین هنگام رسیدن به این هفته

## هدف یادگیری

اطلاعات مخزن را با API امن و صفحه‌بندی‌شده بازیابی کنی.

## اصل مفهومی

REST منابع را از Endpointها برمی‌گرداند؛ GraphQL اجازه انتخاب فیلدهای دقیق می‌دهد. احراز هویت، Rate Limit، Pagination و خطاهای API بخش مهم توسعه ابزارند.

## دستورها و اصطلاحات نمونه

- `gh api repos/arash13/LearningGitAndGithub-ZerotoHero`
- `gh api user`
- `gh api --paginate repos/OWNER/REPO/issues`

**دقت:** بعضی دستورها `OWNER`، `REPO` و شناسه نمونه دارند و قبل از اجرا باید با مقدار واقعی جایگزین شوند. کار با ابزار پولی یا دسترسی سازمانی در صورت نبود مجوز با سناریوی شبیه‌سازی انجام می‌شود.

## آزمایش عملی

اسکریپتی بنویس که Issueهای باز را بدون افشای توکن فهرست کند، داده را فیلتر کند و گزارش Markdown بسازد.

گزارش باید وضعیت اولیه، اقدامات انجام‌شده، شواهد نتیجه، اشتباه‌ها و منطق انتخاب راهکار را نشان بدهد.

## آزمون پایان هفته

1. REST و GraphQL را از نظر ساختار Query مقایسه کن.
2. Rate Limit را چطور مدیریت می‌کنی؟
3. چرا پیام خطای HTTP باید بررسی شود؟
4. **آزمون عملی و دفاع:** یک نمونه مستقل از سناریوی درس اجرا کن، مدرک ارائه بده و ریسک یا جایگزین راه‌حل را توضیح بده.

## ایمنی

توکن را داخل سورس‌کد یا فایل عمومی ذخیره نکن. APIهایی که مجوز بیشتر می‌خواهند صرفاً بررسی نظری می‌شوند.
