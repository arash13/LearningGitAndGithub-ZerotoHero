# هفته 23 | Webhooks، GitHub Apps و OAuth Apps

**فاز:** 6 | **وضعیت:** طرح درس برای تکمیل و تمرین هنگام رسیدن به این هفته

## هدف یادگیری

یک رویداد GitHub را به یک عمل مجاز در ابزار خارجی وصل کنی.

## اصل مفهومی

Webhook رویداد را به آدرس مشخص ارسال می‌کند؛ GitHub App با مجوزهای دقیق‌تر و توکن‌های نصب کار می‌کند. OAuth App و GitHub App مدل‌های متفاوت یکپارچه‌سازی‌اند.

## دستورها و اصطلاحات نمونه

- `gh api repos/OWNER/REPO/hooks`
- `gh api apps/APP_SLUG`

**دقت:** بعضی دستورها `OWNER`، `REPO` و شناسه نمونه دارند و قبل از اجرا باید با مقدار واقعی جایگزین شوند. کار با ابزار پولی یا دسترسی سازمانی در صورت نبود مجوز با سناریوی شبیه‌سازی انجام می‌شود.

## آزمایش عملی

یک Webhook آزمایشی را در محیط امن شبیه‌سازی کن، امضای Payload را بررسی کن و پاسخ مناسب برای رویداد Issue را طراحی کن.

گزارش باید وضعیت اولیه، اقدامات انجام‌شده، شواهد نتیجه، اشتباه‌ها و منطق انتخاب راهکار را نشان بدهد.

## آزمون پایان هفته

1. چرا باید امضای Webhook را تأیید کرد؟
2. Retry و Idempotency چه مسئله‌ای را حل می‌کنند؟
3. چرا App با حداقل Permission بهتر است؟
4. **آزمون عملی و دفاع:** یک نمونه مستقل از سناریوی درس اجرا کن، مدرک ارائه بده و ریسک یا جایگزین راه‌حل را توضیح بده.

## ایمنی

آدرس دریافت رویداد باید امن باشد؛ Secretهای Webhook در مخزن عمومی قرار نگیرند.
