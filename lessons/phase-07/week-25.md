# هفته 25 | GitHub Flow، Git Flow، Trunk-Based و Monorepo

**فاز:** 7 | **وضعیت:** طرح درس برای تکمیل و تمرین هنگام رسیدن به این هفته

## هدف یادگیری

برای هر تیم رویکرد شاخه‌بندی و انتشار را با استدلال انتخاب کنی.

## اصل مفهومی

GitHub Flow مسیر ساده شاخه کوتاه + PR دارد؛ Git Flow روی شاخه‌های عمر‌دارتر برای انتشار تاکید می‌کند؛ Trunk-Based ادغام پیوسته و شاخه‌های کوتاه را ترجیح می‌دهد.

## دستورها و اصطلاحات نمونه

- `git branch -vv`
- `git log --graph --oneline --all`
- `git merge --ff-only FEATURE`

**دقت:** بعضی دستورها `OWNER`، `REPO` و شناسه نمونه دارند و قبل از اجرا باید با مقدار واقعی جایگزین شوند. کار با ابزار پولی یا دسترسی سازمانی در صورت نبود مجوز با سناریوی شبیه‌سازی انجام می‌شود.

## آزمایش عملی

برای محصول وب با انتشار روزانه و محصول سازمانی با انتشار فصلی دو راهبرد متفاوت طراحی کن؛ نقطه شکست و معیار سنجش را ذکر کن.

گزارش باید وضعیت اولیه، اقدامات انجام‌شده، شواهد نتیجه، اشتباه‌ها و منطق انتخاب راهکار را نشان بدهد.

## آزمون پایان هفته

1. چه زمانی Git Flow پیچیدگی بی‌فایده ایجاد می‌کند؟
2. Feature Flags چه ارتباطی با Trunk-Based دارد؟
3. Monorepo چه هزینه و مزیتی دارد؟
4. **آزمون عملی و دفاع:** یک نمونه مستقل از سناریوی درس اجرا کن، مدرک ارائه بده و ریسک یا جایگزین راه‌حل را توضیح بده.

## ایمنی

از یک مدل واحد برای همه تیم‌ها تقلید نکن؛ وابستگی و الگوی انتشار را تحلیل کن.
