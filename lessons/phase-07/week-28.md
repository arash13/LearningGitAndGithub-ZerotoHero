# هفته ۲۸ | پروژه نهایی و دفاع فنی

**فاز:** ۷ | **سطح:** ارزیابی جامع | **پروژه:** TaskFlow

## مأموریت

یک پروژه کوچک مدیریت وظایف بساز که با Git و GitHub به‌صورت قابل بررسی توسعه داده شده باشد. در صورت نیاز از کد نمونه ساده استفاده کن؛ ارزیابی اصلی این دوره درباره ابزارهای Git و GitHub است.

## شرایط اجباری تحویل

- مخزن منظم با `README.md`، `LICENSE` مناسب، `CONTRIBUTING.md`، `.gitignore` و راهنمای اجرا.
- حداقل ۱۰ Issue مستند و یک Milestone یا برد مدیریت کار.
- چند شاخه کوتاه‌عمر، حداقل ۳ PR واقعی با توضیح هدف و چگونگی تست و بررسی اختلاف.
- دست‌کم یک تعارض کنترل‌شده و گزارش نحوه حل آن.
- سابقه معنادار Commitها با پیام‌های روشن و امکان خواندن تاریخچه.
- یک Workflow ساده CI که پس از تغییرات آزمایش یا بررسی صحت را انجام دهد.
- حداقل یک Tag و یک Release با یادداشت تغییرات و در صورت مناسب بودن Pages یا Artifact.
- بازبینی امنیت مخزن، وابستگی‌ها، مجوز Workflow و اطمینان از نبود Secret واقعی.
- یک گزارش عیب‌یابی با `git log` / `bisect` یا `reflog` روی مخزن تمرینی.
- سند تصمیم‌گیری برای روش Branching، سیاست Merge، سطح مجوزها و راهکار بازیابی.

## روش دفاع

۱. بدون رجوع به پاسخ آماده نشان بده کار از شاخه جدید تا PR و انتشار چگونه انجام می‌شود.
۲. یک خطای ناشناخته در مخزن آزمایشی را با ابزارهای مناسب تشخیص بده.
۳. تفاوت سه سناریو را شرح بده: تغییر محلی ثبت‌نشده، Commit منتشرشده اشتباه، تعارض Merge.
۴. درباره Trade-offهای انتخاب GitHub Flow، Trunk-Based یا Git Flow استدلال کن.
۵. شواهد هر بند را با لینک Commit / PR / Issue / Workflow / Release ارائه کن.

## نکته مهم

ابزارهای سازمانی و بعضی امکانات پیشرفته ممکن است در حساب شخصی قابل اجرا نباشند. برای آن بخش‌ها شبیه‌سازی سناریو و دفاع تصمیم‌گیری پذیرفته می‌شود. ادعای «متخصص» نیازمند توان حل مسئله در کار واقعی و تمرین تکرارشونده است.
