# هفته 06 | Remote، Clone، Fetch، Pull و Push

**فاز:** 2 | **وضعیت:** طرح درس، آماده تکمیل تعاملی هنگام رسیدن به این هفته

## نتیجه مورد انتظار

رابطه مخزن محلی و مخزن روی GitHub را دقیق بفهمی.

## مدل ذهنی

fetch اطلاعات را دریافت می‌کند؛ pull علاوه بر دریافت، تغییرها را وارد شاخه کاری می‌کند؛ push نتیجه محلی را به Remote می‌فرستد. شاخه remote-tracking نمای محلی از وضعیت remote است.

## واژه‌ها و دستورهای کلیدی

- `git remote -v`
- `git fetch origin`
- `git branch -avv`
- `git pull --ff-only`
- `git push -u origin feature/example`

> هر دستور را قبل از اجرا از نظر پوشه فعلی، شاخه، تغییرات ثبت‌نشده و اثر بر Remote بررسی می‌کنیم. این فهرست، جایگزین آموزش عملی جلسه نیست.

## مثال و آزمایش هفته

**سناریو:** در مخزن تمرینی دو کپی محلی بساز، از یکی Commit بفرست، در دومی fetch کن و پیش از merge اختلاف را ببین.

گزارش باید شامل وضعیت اولیه، کار انجام‌شده، نتیجه قابل مشاهده، یک اشتباه و نحوه بررسی یا اصلاح آن باشد. نتیجه را با Link به Commit/PR/Issue یا خروجی سانسورشده ثابت کن.

## آزمون پایان هفته

1. fetch چرا معمولاً از pull قابل پیش‌بینی‌تر است؟
2. origin چیست؟
3. چرا push ممکن است non-fast-forward خطا بدهد؟

4. **آزمون عملی:** سناریو را با روش خودت کامل اجرا کن، وضعیت نهایی را ثابت کن و توضیح بده چرا این راهکار را انتخاب کردی.

## نکته ایمنی

برای جلوگیری از Push تصادفی روی main، تمرین را روی شاخه مشخص انجام بده.
