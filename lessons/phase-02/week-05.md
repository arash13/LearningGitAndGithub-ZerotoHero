# هفته 05 | Branch، Merge و Conflict

**فاز:** 2 | **وضعیت:** طرح درس، آماده تکمیل تعاملی هنگام رسیدن به این هفته

## نتیجه مورد انتظار

توسعه موازی و حل تعارض را انجام بده.

## مدل ذهنی

شاخه اشاره‌گر به Commit است. Git هنگام ادغام تغییرهای سازگار آن‌ها را ترکیب می‌کند؛ تعارض یعنی تصمیم انسانی لازم است.

## واژه‌ها و دستورهای کلیدی

- `git switch -c feature/hello`
- `git branch -vv`
- `git switch main`
- `git merge feature/hello`
- `git status`

> هر دستور را قبل از اجرا از نظر پوشه فعلی، شاخه، تغییرات ثبت‌نشده و اثر بر Remote بررسی می‌کنیم. این فهرست، جایگزین آموزش عملی جلسه نیست.

## مثال و آزمایش هفته

**سناریو:** در دو شاخه یک خط یکسان را متفاوت ویرایش کن، تعارض بساز، فایل را آگاهانه اصلاح کن و Commit نهایی بزن.

گزارش باید شامل وضعیت اولیه، کار انجام‌شده، نتیجه قابل مشاهده، یک اشتباه و نحوه بررسی یا اصلاح آن باشد. نتیجه را با Link به Commit/PR/Issue یا خروجی سانسورشده ثابت کن.

## آزمون پایان هفته

1. شاخه جدید کپی کامل فایل‌هاست یا اشاره‌گر به تاریخچه؟
2. Fast-forward با merge commit چه فرقی دارد؟
3. نشانه‌های conflict را در کدام فایل می‌بینی؟

4. **آزمون عملی:** سناریو را با روش خودت کامل اجرا کن، وضعیت نهایی را ثابت کن و توضیح بده چرا این راهکار را انتخاب کردی.

## نکته ایمنی

برای تمرین از شاخه‌های محلی استفاده کن؛ روی main اصلی تجربه تصادفی انجام نده.
