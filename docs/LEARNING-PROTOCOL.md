# پروتکل آموزش و ارزیابی

## روش تدریس

آموزش به فارسی ساده است. دستورها، نام گزینه‌ها، پیام خطا و نام فایل‌ها به انگلیسی می‌مانند. برای هر مبحث ابتدا «چرا و چه زمانی؟» و سپس «چطور؟» مطرح می‌شود.

- **فهم:** مفهوم را با مثال روزمره و تصویر ذهنی توضیح بده.
- **پیش‌بینی:** پیش از اجرای دستور، خروجی و اثر آن را حدس بزن.
- **اجرا:** فقط در مخزن تمرینی امن دستور را اجرا کن.
- **بررسی:** از `git status`، `git diff` و `git log` استفاده کن.
- **حل مسئله:** یک خطای عمدی ایجاد و ترمیم کن.
- **آزمون:** بدون کپی پاسخ آماده، مسئله مستقل را حل کن.

## ساختار مدارک

- گزارش هر جلسه: `progress/PROGRESS.md` با تاریخ، نمره و لینک مدرک.
- تمرین‌های هر هفته: پوشه `exercises/week-NN/` بعد از رسیدن به همان هفته ساخته می‌شود.
- Pull Requestهای تمرین: توضیح هدف، مراحل تست و خطرات احتمالی.
- کامیت‌ها: کوچک و معنادار، مثل `docs: record week 01 observations` و `exercise: add staged snapshot example`.
- برای سنجش واقعی، **متن پاسخ آزمون را پیش از بررسی از مربی نخواه.**

## حفظ امنیت مخزن عمومی

کلید خصوصی SSH، رمز عبور، توکن، کوکی، فایل `.env` واقعی، ایمیل شخصی و اطلاعات محرمانه را هرگز Commit نکن. برای تمرین از داده ساختگی استفاده کن. خروجی ترمینال را قبل از ثبت بررسی کن.

## گواهی مهارت و سوابق

ادعای «مسلط شدم» با مدرک همراه است: لینک به commit، PR، Issue، Workflow یا گزارش حل مسئله. تکمیل چک‌لیست به‌تنهایی معادل مهارت نیست. در پایان هر فاز یک آزمون سناریویی مستقل برگزار می‌شود.
