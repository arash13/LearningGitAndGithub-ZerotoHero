# واژه‌نامه ساده

| واژه | توضیح کوتاه |
|---|---|
| Version control | پیگیری تاریخچه تغییرات فایل‌ها |
| Repository (Repo) | محل داده‌ها و تاریخچه یک پروژه |
| Working tree | فایل‌هایی که اکنون روی آن‌ها کار می‌کنی |
| Staging area / Index | تغییراتی که برای Commit بعدی انتخاب شده‌اند |
| Commit | ثبت یک وضعیت و اطلاعات مرتبط در تاریخچه |
| HEAD | مرجعی که موقعیت فعلی کار را مشخص می‌کند |
| Branch | نام یا اشاره‌گر متحرک به یک Commit |
| Merge | ترکیب تاریخچه تغییرات |
| Conflict | شرایطی که Git برای ترکیب خودکار نیازمند تصمیم تو است |
| Remote | نام یک مخزن دیگر، معمولاً روی سرویس میزبانی |
| Clone | ساخت یک کپی محلی با اطلاعات مخزن |
| Fetch | دریافت اطلاعات Remote بدون ادغام در شاخه فعلی |
| Pull | Fetch و سپس ادغام یا Rebase مطابق تنظیمات |
| Push | ارسال Commitها و Refهای محلی به Remote |
| Fork | کپی یک مخزن زیر حسابی دیگر در GitHub |
| Issue | واحد پیگیری کار، باگ یا درخواست |
| Pull Request (PR) | درخواست بررسی و ادغام تغییرات |
| Code Review | بررسی تغییرات با هدف کیفیت و درستی |
| Actions | موتور اتوماسیون GitHub |
| Workflow | تعریف مجموعه Jobهای خودکار |
| Runner | محیطی که Workflow را اجرا می‌کند |
| GitHub App | برنامه یکپارچه‌شده با GitHub با مجوزهای مشخص |
| Ruleset | مجموعه قوانین اعمال‌شده به Refها یا جریان کار |
| CI/CD | بررسی و تحویل یا انتشار خودکار نرم‌افزار |
| Rebase | بازپخش Commitها روی مبنای جدید و بازنویسی شناسه آن‌ها |
| Reflog | سابقه محلی جابه‌جایی بعضی Refها |
